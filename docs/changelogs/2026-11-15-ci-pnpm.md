# 2026-11-15 — CI and Makefile use pnpm for the frontend

| | |
|---|---|
| Author | agent |
| Scope | `.github/workflows/build.yml`, `Makefile` |
| Requirements | none (build tooling) |

## Changed
- The `frontend` job installs pnpm (`pnpm/action-setup@v4`, version 10) before `actions/setup-node`,
  caches with `cache: pnpm` keyed on `frontend/pnpm-lock.yaml`, installs with
  `pnpm install --frozen-lockfile` and builds with `pnpm run build`. It no longer references
  `package-lock.json`, which the frontend submodule dropped when it moved to pnpm.
- `make ui-install`, `ui-build`, `ui-lint`, `ui-test`, `ui-check-api` and `ui-dev` call pnpm instead of npm.

## Verification
- `make -n ui-build ui-check`: the commands expand to pnpm as intended.
- `pnpm install --frozen-lockfile` and `pnpm run build --outDir /tmp/... --emptyOutDir` in `frontend/`
  (local pnpm 12.16.1): both succeed.
- Not run: the GitHub Actions workflow itself (needs a push); pnpm 10 in CI was not exercised locally.

## Known gaps / follow-ups
- `frontend/package.json` has no `packageManager` field, so the pnpm version is pinned in the workflow.
  If the submodule adds one, drop `version:` from `pnpm/action-setup`.
- Docs still say `npm run gen:api` / `check:api` (`requirements/http-api.md`, `web-ui.md`, `roadmap.md`,
  `reports/frontend-api-integration.md`); they describe past sessions and are left as written.
