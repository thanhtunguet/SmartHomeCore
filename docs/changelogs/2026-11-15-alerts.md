## Added
- **Alert channels.** A channel is a destination served by an adapter, with a name, `enabled`, the `events` it wants, non-secret `settings` and one sealed `secret`. Managed by `GET/POST /alerts/channels`, `GET/PATCH/DELETE /alerts/channels/{id}` and `POST /alerts/channels/{id}/test` (spec first, `make generate`). Table `alert_channels` (migration `0008`).
- **Telegram adapter** with the two requested parameters: `secret` = bot token, `settings.target_user_id` = target user id. Plain-text `sendMessage` over the standard library (no new dependency). Adding another adapter is one `Factory` plus a spec enum value.
- **Three events**, each a hook where the fact is known:
  - `ip_changed`: `ddns.Service.Sync` moved a record to a new address (scheduler and manual sync). Message: record, type, `old → new`.
  - `power_command`: `commands.Engine.Request` created and dispatched a wake or shutdown (REST, legacy endpoints and MCP alike). Message: device, what happened, who asked ("By alice (service key)"); a failed dispatch is announced as failed.
  - `status_changed`: the monitor recorded online↔offline and no wake/shutdown command in progress explains it (wake explains `online`, shutdown explains `offline`). First sightings and disabled devices are ignored.
- Delivery: `Notify` only queues (64 entries); `alerts.Service.Run` (a new errgroup member) delivers in order, channels in parallel, up to 3 attempts (1 s, 5 s) on temporary errors, and stores `last_sent_at` / `last_error` / `last_error_at` on the channel.
- Audit `alert_channel.create|update|delete|test` (field names only) and activity-feed messages for them.
- `alertstest`: an in-memory Telegram Bot API for tests.

## Changed
- `ddns.ServiceConfig.Observer`, `commands.Config.Issued`, `monitoring.Config.Transitions` / `SetTransitionObserver`: optional observers; behaviour without one is unchanged. `monitoring` calls the transition hook **before** the existing Observer so the alert can still see the command that is about to be completed.
- `ddns.Outcome` gained `IPChanged` and `PreviousIP` (not persisted).
- Test environment of `internal/api` (`devEnv`) wires the alert service against a fake Telegram.

## Security
- The bot token is sealed (AAD `alert_channels.secret`), write-only (`has_secret`) and absent from responses, logs, audit rows and `last_error`. The Bot API puts the token in the URL, so the adapter strips the URL from transport errors and scrubs the token from Telegram's replies; tests check each path (REQ-SEC-007).
- Alert endpoints are session-only: a service account key (even `mcp`) gets `403`.
- No change to the Agent, the signed protocol, the throttle or any invariant in `CLAUDE.md`.
