## Functional requirements

| ID | Requirement | Status | Verified by |
|----|-------------|--------|-------------|
| REQ-AG-001 | The Agent runs its own listener (default `:9750`) with exactly two endpoints: `POST /agent/v1/commands` and the unauthenticated `GET /agent/v1/healthz` (`status`, `agent_id`, `version`). | Implemented | `agent/server_test.go`; smoke test |
| REQ-AG-002 | Commands are authenticated with **Ed25519**. The Agent stores only public keys of trusted Controllers (`agent.trusted_controllers[].public_key`, base64 of 32 bytes). `key_id` = hex of the first 8 bytes of SHA-256(public key). An invalid key stops startup; no keys = warning, every command rejected. | Implemented | `TestVerifyAcceptsValidCommand`; startup validation by smoke test |
| REQ-AG-003 | The command body is JSON `{v, command_id, agent_id, action, issued_at, nonce}`: `v = 1`, UUIDs, `issued_at` in unix seconds, nonce base64url of ≥ 16 random bytes. The body is at most 4 KiB, unknown fields and trailing data are rejected. The signature covers `"homecore-agent-cmd-v1\n" + key_id + "\n" + body` exactly, so no canonicalisation is needed. | Implemented | `TestVerifyRejectsUnknownJSONFields`, `TestVerifyRejections/short_nonce` |
| REQ-AG-004 | The signature is checked **before** the body is parsed. An unknown key id and a bad signature give the identical response `401 unauthorized`, so callers learn nothing. | Implemented | `TestVerifyRejections` (unknown key, untrusted signer, tampered body), `TestUnsignedRequestRejected` |
| REQ-AG-005 | Only allowlisted actions run (`agent.allowed_actions`, default `[shutdown]`, optional `reboot`). Unknown actions → `400 bad_request`; known but not allowed → `403 action_not_allowed`. The Agent never runs a shell or takes arguments from requests. | Implemented | `TestVerifyRejections` (action not allowed, unknown action) |
| REQ-AG-006 | Freshness: `|agent_now − issued_at| ≤ clock_skew` (default 30 s, configurable 5 s–5 m), otherwise `401 clock_skew`. Every response includes `agent_time` so drift can be diagnosed. | Implemented | `TestVerifyRejections` (too old, from the future) |
| REQ-AG-007 | Each nonce is single-use for 2 × `clock_skew`; reuse → `409 replay`. The nonce cache holds at most 10 000 entries and **fails closed** (`503 busy`) when full. | Implemented | `TestVerifyRejectsReplay`, `TestExpiringSetFailsClosedWhenFull` |
| REQ-AG-008 | Idempotency: a `command_id` already accepted in the last 10 minutes returns `200 already_accepted` and does not run again (Controller retries reuse `command_id` with a fresh nonce). While a power action is scheduled or in its cooldown (default 60 s), other commands get `200 already_scheduled`. | Implemented | `TestShutdownIsAcknowledgedThenExecutedOnceAndIdempotent` |
| REQ-AG-009 | Acknowledge before executing: an accepted command returns `202 accepted` with `execute_at`, and the action runs after `action_delay` (default 3 s). If the Agent stops before then, the pending action is cancelled and logged. | Implemented | `TestShutdownIsAcknowledgedThenExecutedOnceAndIdempotent` (cancel path untested) |
| REQ-AG-010 | Addressing: the Agent has a persistent `agent_id` (UUIDv7 in `<agent.data_dir>/agent_id`, mode `0600`, created on first start and logged). A command for another `agent_id` → `403 wrong_agent`. | Implemented | `TestVerifyRejections/wrong_agent` |
| REQ-AG-011 | Least privilege: on Linux the action is `systemctl poweroff|reboot --no-wall` with fixed arguments, run as the unprivileged user `homecore-agent`. Authorisation comes from a polkit rule allowing only the four `org.freedesktop.login1.power-off*/reboot*` actions to that user, under a hardened systemd unit. Windows: see REQ-AG-015. Other platforms, or `dry_run: true`, only log the action. | Implemented (untested on a host) | Code review; macOS dry-run smoke test |
| REQ-AG-012 | Transport: optional TLS (`agent.tls`). The listener is meant for the LAN only; remote access goes through a VPN (documented in config comments and `deploy/README.md`). | Implemented (TLS untested) | — |
| REQ-AG-013 | Replay across restarts: commands with `issued_at` earlier than the Agent's start time → `401 stale`, so losing the in-memory nonce cache on restart opens no window. | Implemented | `TestVerifyRejections/issued_before_agent_start` |
| REQ-AG-014 | Every rejected command is logged with remote address, error code and reason; every processed command with `command_id`, action, outcome and `execute_at`. | Implemented | Smoke-test log |
| REQ-AG-015 | Windows power adapter (`internal/platform/power_windows.go`). The Agent is run **elevated** (Administrator, or a service account holding `SeShutdownPrivilege`). Before each action it enables `SeShutdownPrivilege` on its own token, then calls `InitiateSystemShutdownExW` on the local machine with timeout 0, a fixed message, a fixed reason (planned, "Other") and **applications closed by force** (a remote request cannot answer a "save changes?" dialog; unsaved data is lost). `shutdown` powers off, `reboot` restarts. No shell, no arguments from requests. If the shutdown call is refused (`ERROR_ACCESS_DENIED`) the error says to run as Administrator. A cancelled context does nothing. `dry_run: true` still only logs. | Implemented (untested) | `platform.TestWindowsPowerEnablesPrivilegeThenInitiates`, `TestWindowsPowerDoesNotShutDownWithoutThePrivilege`, `TestWindowsPowerAccessDeniedExplainsTheFix`, `TestWindowsPowerHonoursACancelledContext` (fakes for the two Win32 calls; they compile and vet for `GOOS=windows` but were **not executed**, no Windows host), `make cross` |

## Controller side (Phase 3)

Tests named here are in `internal/controllerkey`, `internal/agentctl`, `internal/api` (the integration
tests start the real Controller router and a real `internal/agent` server with a fake
`PowerController`; `internal/app` runs `--mode both` through `app.Run`) and `cmd/homecore`.

| ID | Requirement | Status | Verified by |
|----|-------------|--------|-------------|
| REQ-SHD-001 | **Controller key.** An Ed25519 key pair is generated from `crypto/rand` on first start and stored in `controller_keys`: the public key as a 32-byte blob, the private key (its 32-byte seed) sealed with the master key under the AAD `controller_keys.private_key`. `key_id` is the protocol's (hex of the first 8 bytes of SHA-256(public key)). At most one key is active (`controller_keys_one_active`); the key is loaded at every start and is **never replaced silently**: a wrong master key or a row whose public key does not match the private key stops the Controller with a message. It is independent of the JWT signing key and the master key. First creation writes an `audit_log` entry (`controller_key.create`) and logs the `key_id`. The private key is never logged, formatted or returned. Key rotation is not implemented. | Implemented | `controllerkey.TestKeyIsCreatedOnceSealedAndStable`, `TestKeyIsDistinctFromJWTAndMasterKey`, `TestWrongMasterKeyIsAnErrorNotAReplacement`, `TestTamperedRowIsRejected`, `TestConcurrentFirstUseYieldsOneKey`, `TestDatabaseAllowsOnlyOneActiveKey`, `TestKeyNeverFormatsItsPrivatePart`; `TestBothModeShutdownEndToEnd` (kept across start) |
| REQ-SHD-002 | **Publishing the key.** `GET /api/v1/system/controller-key` (any authenticated user, REQ-API-024) and `homecore key show [--config] [--data-dir]` print `key_id`, `algorithm` (`ed25519`) and the base64 public key, the latter with a ready `agent.trusted_controllers` snippet. The CLI works on the database file (no running Controller needed) and, when the Controller never ran, generates the key exactly as the Controller does (it will use that same key) so an Agent can be configured first. | Implemented | `api.TestControllerKeyEndpoint`, `api.TestAgentTrustingTheAPIKeyAcceptsTheDispatcher`, `main.TestKeyShowCreatesThenReprintsTheSameKey`; smoke test 2026-11-14 |
| REQ-SHD-003 | **Request.** The shutdown Dispatcher builds `{v:1, command_id = the command id, agent_id = the binding's, action:"shutdown", issued_at = now, nonce = 16 fresh random bytes}`, signs it with the Controller key (`protocol.Sign`) and sends `POST <scheme>://<host>:<agent port>/agent/v1/commands` with `Content-Type: application/json`, `X-HomeCore-Key-Id` and `X-HomeCore-Signature`, one attempt bounded by 2 s. `<host>` is the address the monitor probes (`hostname` if set, else `ip_address`; IPv6 in brackets). The HTTP client uses no proxy (the environment's `HTTP_PROXY` is ignored), follows no redirects, reuses no connections and reads at most 8 KiB. `https` bindings are verified against the system trust store (pinned/self-signed agent certificates are not supported yet). | Implemented | `agentctl.TestDispatchSendsASignedProtocolRequestAndAcknowledges` (the Agent's own `protocol.Verifier` accepts it), `TestAgentURL`, `api.TestShutdownEndToEndWithARealAgent` |
| REQ-SHD-004 | **Success.** `202 accepted` and `200 already_accepted` / `already_scheduled` (REQ-AG-008) from the bound agent (body `agent_id` and `command_id` match) make the command `acknowledged` (the engine records `sent` and `acknowledged` together). Any other 2xx, or an unparseable body, or another `agent_id` is a failure `agent_bad_response`. | Implemented | `agentctl.TestAlreadyAcceptedAndAlreadyScheduledAreSuccess`, `TestUnexpectedAnswersAreNotSuccess`, `api.TestShutdownEndToEndWithARealAgent` |
| REQ-SHD-005 | **Agent rejection.** A 4xx from the agent fails the command at once (never retried) with the agent's `error.code` as `error_code` when it is one of the protocol's (`unauthorized`, `bad_request`, `wrong_agent`, `action_not_allowed`, `clock_skew`, `stale`, `replay`, `busy`) and a human `error` text that adds the operator hint: `unauthorized` names the Controller's `key_id`; `clock_skew` shows the agent's `agent_time` and the drift from the Controller clock; `action_not_allowed`, `wrong_agent` and `stale` say what to fix. Unknown codes become `agent_error`; remote text is stripped of control characters and cut at 200 characters, and is never copied for unknown codes. | Implemented | `agentctl.TestAgentRejectionsAreFinalAndPassedThrough`, `TestClockSkewTextShowsTheAgentTime`, `TestRemoteTextIsSanitised`, `TestUnexpectedAnswersAreNotSuccess`; `api.TestShutdownWithAnUntrustedKeyFailsWithTheAgentsCode`, `TestShutdownWithClockSkewReportsTheDrift` |
| REQ-SHD-006 | **Retry.** A network error or a 5xx on the first attempt is retried **once, immediately**, with the same `command_id` and a new nonce and `issued_at` (the Agent makes the retry idempotent, protocol step 10); then the command is `failed`. A 4xx is never retried. There is no backoff and no loop; `attempts` records 1 or 2. | Implemented | `agentctl.TestFiveHundredIsRetriedOnceWithTheSameCommandIDAndANewNonce`, `TestPersistentFiveHundredStopsAfterTwoAttempts`, `TestNetworkErrorIsRetriedOnceThenAgentUnreachable` |
| REQ-SHD-007 | **Controller-side error codes** of a failed shutdown (agent codes in REQ-SHD-005 are passed through): `agent_unreachable` (connection refused, reset, no route, DNS or TLS failure), `agent_timeout` (no answer within 2 s), `agent_bad_response` (HTTP answer that is not a HomeCore agent: HTML, 404, redirect, wrong body), `agent_error` (5xx after the retry without a protocol body, or an unknown error code), `dispatch_error` (signing or request-building failure on the Controller). Fail fast: a dead agent fails the command within about 4 s at worst (2 × 2 s timeouts) and in milliseconds for a refused connection; the HTTP request itself is still `202`. | Implemented | `agentctl.TestConnectionRefusedIsAgentUnreachableAndFast`, `TestSlowAgentIsATimeoutNotAHang`, `TestUnexpectedAnswersAreNotSuccess`, `TestPrecheckAndDispatchErrors`; `api.TestShutdownWithTheAgentDownFailsFast` |
| REQ-SHD-008 | **`POST /devices/{id}/shutdown`** (ADR-012): `202` with the `Command` after dispatch. An active shutdown command is returned unchanged (no new request to the agent). A device whose stored status is `offline` is confirmed by one fresh probe, and if it is really unreachable the command is created `completed` **without contacting the agent**; a stale `offline` on a running machine still gets the shutdown. A device without an agent binding is `409` with a clear message and nothing is stored. Unknown device `404`; more than one request per device per second `429` (REQ-API-018). Wake and shutdown are independent. The command is `completed` when the monitor sees the device `offline` (hysteresis applies) and `timed_out` at `deadline_at` (default 120 s) otherwise (engine, REQ-CMD-006/007). | Implemented | `api.TestShutdownEndToEndWithARealAgent`, `TestShutdownOfAnOfflineDeviceCompletesWithoutContactingTheAgent`, `TestStaleOfflineStatusIsConfirmedByAFreshProbe`, `TestShutdownWithoutAnAgentBindingIs409`, `TestShutdownIsThrottledPerDevice`, `TestShutdownTimesOutWhenTheMachineStaysUp`, `TestWakeAndShutdownAreIndependent`; `commands.TestEngineIsGenericAcrossTypes` |
| REQ-SHD-009 | **Audit.** Every accepted shutdown request writes `audit_log` `device.shutdown` with the acting user (`actor`, `actor_user_id`), the device id (`target_id`), the client address and `details {command_id, status, name}` (plus `error_code` on failure). `result` is `ok` (the command is acknowledged or completed) or `failed` (the command failed). A repeated request writes another entry with the same `command_id`. Rejected requests (`404`, `409`, `429`) write nothing, as for wake. The write follows the dispatch: if the audit insert fails it is logged, not returned, because the same database already refused the command row first. | Implemented | `api.TestShutdownEndToEndWithARealAgent`, `TestShutdownOfAnOfflineDeviceCompletesWithoutContactingTheAgent`, `TestShutdownWithTheAgentDownFailsFast`, `TestShutdownWithAnUntrustedKeyFailsWithTheAgentsCode`, `TestShutdownWithoutAnAgentBindingIs409` |
| REQ-SHD-010 | **Agent status on every contact.** The dispatcher records the outcome of each shutdown attempt on the binding: `ready` when the bound agent answered (accepted, or refused with a protocol 4xx other than `wrong_agent`), `unreachable` for a network error, a 5xx, a non-agent answer or `wrong_agent`; `last_ok_at` moves only on success. A result for an `agent_id` that is no longer the binding's is ignored. Re-binding to another agent, port or scheme resets the status to `unknown`, an identical re-send keeps it. Local failures (signing) are not contacts. | Implemented | `agentctl.TestAgentRejectionsAreFinalAndPassedThrough` (recorded status), `devices.TestAgentContactIsRecordedAndForgottenOnRebind`, `api.TestShutdownWithTheAgentDownFailsFast`, `TestAgentStatusFromTheHealthJobOverHTTP` |
| REQ-SHD-011 | **Health job.** `agentctl.Health` (`Run(ctx)`, wired in `internal/app`) does a pass at start and then **once a minute** (`agentctl.DefaultHealthInterval`, not a config key), with at most 4 requests in flight. For every device with a binding: `online` → `GET /agent/v1/healthz` (2 s); the answer must be `200 {"status":"ok"}` with the **bound `agent_id`**, else `unreachable` (a different agent answering at that address is "wrong agent"); success stores `ready`, `version` (control characters stripped, 64 characters) and `last_ok_at`. `offline` → an agent still `ready` becomes `unreachable` without a request (a machine that is off cannot run its agent). `unknown` → untouched. Status changes are logged, steady states are not. The job stops with its context, starts no goroutine that outlives a pass, and a pass cancelled mid-flight records nothing. Consequence: after a device comes online or is bound, the status can stay `unknown`/`unreachable` for up to one interval unless a shutdown contacts the agent first. | Implemented | `agentctl.TestHealthPassMarksAReachableAgentReady`, `TestHealthRejectsAnotherAgentAnsweringAtTheAddress`, `TestHealthTreatsDeadAndForeignServicesAsUnreachable`, `TestHealthDoesNotContactOfflineOrUnknownDevices`, `TestHealthPassIsBoundedAndComplete`, `TestHealthRunChecksAtStartAndOnEveryTickAndStops` (fake ticks and clock, goroutine check), `TestHealthCancelledPassRecordsNothing` (also under `make test-race`); smoke test 2026-11-14 |
| REQ-SHD-012 | **End to end.** In `--mode both` (`app.Run`) the Controller and the real Agent interoperate: key created first, its public key in `agent.trusted_controllers`, device bound through the API, shutdown → `acknowledged` → the Agent's power controller called exactly once → monitor sees the listener closed → `completed`; the activity feed records it. | Implemented | `app.TestBothModeShutdownEndToEnd`; smoke test with two processes 2026-11-14 |

Not exercised by any test or smoke test: a real power-off, the Windows power adapter, the Linux power adapter (`systemctl` +
polkit) and the systemd unit on a real host, `https` agents, an RTC-less device with a real clock
skew, an agent on another machine.

## Developer tooling

`cmd/devtools` provides `keygen` (Controller key pair: seed file `0600`, prints `key_id` and public
key) and `send` (builds, signs and posts a command; `-command-id` reuse tests idempotency).

## Known gaps

- The accepted-`command_id` map is pruned after 10 minutes but has no size cap, unlike the "bounded
  caches" statement in the protocol spec. Only authenticated callers can add entries, so the risk is
  low; tracked in the roadmap backlog.
- The Controller does not pin or accept self-signed agent certificates; an `https` binding needs a
  certificate the Controller's system trust store accepts (agent-protocol §7, "TLS with pinned
  certificate").
- The Controller key cannot be rotated yet; an Agent may already list several trusted keys, so a
  rotation can be added without a protocol change.
- Agent status lags by up to one health interval after a machine boots or an agent is bound
  (REQ-SHD-011).
- Signed acknowledgements (protocol v2) are not implemented.
- The Windows adapter (REQ-AG-015) has never run on a Windows host, and there is no Windows Service wrapper yet: the Agent is started from an elevated console or Task Scheduler. `agent.data_dir`/`data_dir` defaults to `./data` relative to the working directory, so set it explicitly on Windows.
- The systemd unit and polkit rule have not been validated on a real Linux host.
