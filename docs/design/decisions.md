# Architecture Decision Records

These answer the five open questions from `BRIEF.md` §8 plus the foundational choices. Format:
context → decision → consequences. Status of all records: **Accepted (v0.2)** unless noted.

---

## ADR-001 — Agent command authentication: Ed25519 signatures

**Context.** The Controller must prove to an Agent that a command is authentic, fresh and intended
for that Agent. Options: static secret (rejected by the brief), HMAC-SHA256 with a per-agent shared
secret, Ed25519 signatures.

**Decision.** Ed25519. The Controller owns a signing key pair (private key sealed in its DB). Each
Agent is configured with the **public keys** of the Controllers it trusts (`agent.trusted_controllers`).
Replay protection is mandatory and independent of the signature scheme: timestamp window, nonce
cache, process-start floor and `command_id` idempotency (see [agent-protocol.md](agent-protocol.md)).

**Consequences.**
- A compromised Agent host leaks nothing that can forge commands to other Agents.
- Provisioning is copy-paste of one public key (`GET /api/v1/system/controller-key`, or
  `devtools keygen` during development) into the Agent config; no secret distribution.
- Multiple Controllers are natural (ADR-005).
- Content is authenticated, not encrypted. Confidentiality needs TLS (agent supports optional TLS)
  or a VPN. Commands contain no secrets, so this is acceptable on a home LAN.
- HMAC remains a fallback only if Ed25519 is ever unavailable on a target (it is in Go stdlib, so not
  expected).

## ADR-002 — Device identity

**Context.** DHCP may change IPs; hostnames may be unresolvable; MACs change when a NIC changes.

**Decision.** A device is identified by a server-generated **UUID** (v7). `ip_address`, `hostname` and
`mac_address` are mutable attributes. A device may be bound to an Agent identified by its own
`agent_id` (UUID generated by the Agent on first start and persisted in its data dir). The probe
target is `hostname` when set, otherwise `ip_address`. The command payload carries the target
`agent_id`, and the Agent rejects commands addressed to another `agent_id` — so a stale IP that now
belongs to a different Agent can never execute someone else's shutdown.

**Consequences.** IP changes need a manual edit in MVP. Later: Agent announces itself (signed) so the
Controller can update the IP automatically.

## ADR-003 — Command state machine

**Decision.** `pending → sent → acknowledged → completed | failed | timed_out`, with `wake` skipping
`acknowledged`. Completion is verified **only** by the monitor (online for wake, offline for
shutdown) before a deadline. HTTP endpoints return `202` with the command immediately. A second
request for the same device and type while one is active returns the active command.

**Consequences.** The UI shows honest progress. The brief's `unknown` outcome is called `timed_out` to
avoid a name clash with device status.

## ADR-004 — SQLite driver: `modernc.org/sqlite` everywhere

**Context.** We need one storage implementation for Linux, macOS, Windows and Android (gomobile).
Options: `mattn/go-sqlite3` (cgo, needs C toolchain per target incl. NDK), `modernc.org/sqlite`
(pure Go, transpiled C), `ncruces/go-sqlite3` (Wasm via wazero), or a Kotlin-side storage adapter.

**Decision.** `modernc.org/sqlite` behind `internal/storage`, no Android-specific storage adapter.

**Evidence.** `CGO_ENABLED=0 go build` with the driver succeeds for `android/arm64`, `linux/arm64`,
`linux/arm`, `linux/amd64`, `windows/amd64`, `darwin/arm64`. `android/arm` (32-bit) cannot link
without cgo — a Go toolchain constraint for Android executables, not a driver issue; gomobile always
builds with cgo + NDK, so it is expected to work but **must be verified in the Phase 0 spike**.

**Consequences.** Trivial cross-compilation; larger binary (~+6 MB) and somewhat slower than cgo
SQLite, irrelevant at this load. If the spike fails on a target, fall back to `ncruces/go-sqlite3`
(same `database/sql` interface) without touching domain code.

## ADR-005 — Multiple Controllers

**Decision.**
- Each Controller has its own key pair and `key_id`. An Agent lists all Controllers it trusts.
- Monitoring and WOL from several Controllers are allowed (idempotent, harmless).
- Commands carry a globally unique `command_id`; the Agent executes a given `command_id` at most once
  and, after accepting a power action, ignores further power actions during a cooldown
  (default 60 s), answering `already_scheduled`.
- No leader election or Controller-to-Controller sync in MVP. Each Controller keeps its own DB.

**Consequences.** Two Controllers can show slightly different histories; that is accepted.

## ADR-006 — Spec-first REST API

**Decision.** `api/openapi.yaml` (OpenAPI 3.0.3) is the source of truth. `oapi-codegen` (pinned as a
Go `tool` dependency) generates models, a chi `ServerInterface` and the embedded spec into
`internal/api/gen`. Generated code is committed; CI checks it is up to date (`make generate && git
diff --exit-code`). Handlers embed `gen.Unimplemented` so documented-but-unbuilt operations return 501.

**Consequences.** Docs cannot drift from routes or request/response shapes. Contributors (and AI
agents) change the YAML first, then regenerate, then implement.

---

## ADR-007 — Modular monolith, minimal layering

**Decision.** One Go module, packages per capability under `internal/`. Consumer-side interfaces,
constructor injection in `internal/app`, no DI framework, no global state. Layers (model / service /
repository) are added per package only when justified.

---

## ADR-008 — Offline Swagger UI

**Decision.** Pinned `swagger-ui-dist` assets are committed under `web/swagger/` (fetched once by
`scripts/fetch-swagger-ui.sh`) and embedded with `//go:embed`. The page loads `/api/openapi.json`
from the same origin. No CDN at runtime.
